# システム要件定義書 (REQUIREMENTS.md)

## 1. はじめに

### 1.1 目的
本ドキュメントは、「V2X（Vehicle-to-Everything）協調型自動運転統合システム」のシステム要件を定義するものである。本システムは、車両、インフラ、歩行者、ネットワーク（クラウド）間でのリアルタイム通信を通じて、高度な協調型自動運転を実現し、交通事故ゼロ、交通効率の最適化を目指す。

### 1.2 スコープ
本システムの対象範囲は以下の通りである。
*   **車載システム (On-Board Unit: OBU)**: センサー処理、自己位置推定、経路計画、V2X通信、車両制御。
*   **路側システム (Road Side Unit: RSU)**: 交差点監視、信号情報配信、エッジコンピューティング。
*   **クラウドシステム**: フリート管理、HDマップ配信、OTA更新、ビッグデータ分析。

## 2. システム規模・性能要件

### 2.1 規模
*   **総コード規模目標**: 230,000行超（C++, Python, Rust, Go等の合計）
*   **接続車両数**: 100万台同時接続
*   **対象エリア**: 都市部、高速道路、郊外を含む広域エリア

### 2.2 性能指標 (KPI)
*   **V2X通信レイテンシ**: < 10ms (DSRC/C-V2X/5G NR-V2X)
*   **地図更新頻度**: HD Map差分更新 < 1秒（配信完了まで）
*   **センサーデータ処理**: 10Gbps/車両 (LiDAR + 8 Camera + Radar)
*   **システム可用性**: 99.9999% (Six Nines)
*   **測位精度**: ±5cm (RTK-GNSS + V2X補正)

## 3. 準拠規格・標準

### 3.1 機能安全・安全性
*   **ISO 26262**: 自動車向け機能安全規格 (ASIL-D対応)
*   **ISO/PAS 21448 (SOTIF)**: 意図した機能の安全性
*   **ISO 21434**: 自動車サイバーセキュリティ

### 3.2 V2X通信規格
*   **ETSI ITS-G5**: 欧州ITS標準 (IEEE 802.11pベース)
*   **3GPP Release 16**: 5G NR-V2X (Sidelink/Uu)
*   **IEEE 1609.x (WAVE)**: 米国ITS標準
*   **SAE J2735/J2945**: V2Xメッセージセットおよび性能要件

### 3.3 データフォーマット・その他
*   **AUTOSAR Adaptive Platform**: 車載ソフトウェア標準
*   **OpenDRIVE 1.8 / Lanelet2**: 高精度地図フォーマット
*   **ASAM OpenSCENARIO 2.0**: シナリオ記述言語

## 4. 機能要件

### 4.1 車載システム (OBU)
*   **センサーフュージョン**: LiDAR, Camera, Radar, Ultrasonicのデータを統合し、360度環境認識を行うこと。
*   **V2X通信**: BSM/CAM/DENM等のメッセージを10Hz以上で送受信し、周辺車両・インフラと協調すること。
*   **経路計画・制御**: 動的な環境変化に対応し、安全かつ快適な経路を生成・追従すること。

### 4.2 路側システム (RSU)
*   **交差点監視**: 交差点内の全オブジェクトを検出し、SPAT (信号情報) および MAP (地図情報) を配信すること。
*   **エッジ処理**: 通信遅延を最小化するため、緊急度の高い処理（衝突警告等）をエッジで実行すること。

### 4.3 クラウドシステム
*   **デジタルツイン**: 現実世界の交通状況をリアルタイムに仮想空間へ反映し、シミュレーションを行うこと。
*   **SCMS (Security Credential Management System)**: V2X通信の信頼性を担保するため、証明書の発行・管理を行うこと。

## 5. 非機能要件

### 5.1 セキュリティ
*   **V2X PKI**: 公開鍵基盤を用いた相互認証とメッセージ署名。
*   **プライバシー保護**: 仮名証明書 (Pseudonym Certificate) の定期的な変更。
*   **量子耐性暗号**: 将来的な脅威に備え、CRYSTALS-Kyber等のアルゴリズムを採用すること。

### 5.2 信頼性・可用性
*   **冗長化**: サーバー、ネットワーク、電源等の単一障害点 (SPOF) の排除。
*   **フェイルセーフ**: システム障害時に安全な状態へ移行する機構（Minimum Risk Maneuver）。

### 5.3 拡張性・保守性
*   **マイクロサービスアーキテクチャ**: 機能単位での独立したデプロイ・スケールが可能であること。
*   **OTA (Over-The-Air) 更新**: 車両ソフトウェアおよび地図データの遠隔更新機能。
