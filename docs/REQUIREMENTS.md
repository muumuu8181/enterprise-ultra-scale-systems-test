# Core Banking System Requirements (Step 1-10)

## 機能要件 (Functional Requirements)

### 1. 預金系システム (Deposit System)
- **口座管理**:
  - 普通預金、定期預金、当座預金、貯蓄預金口座の開設・解約・管理
  - 口座番号生成、顧客情報との紐付け
  - 残高照会（現在残高、前日残高、平均残高）
- **取引処理**:
  - 入金・出金・振替（内部振替、他行振込）
  - 取引履歴の記録
  - リアルタイムな残高更新
- **利息計算**:
  - 毎日の利息計算、月末締め処理
  - 複利、単利計算
  - 源泉徴収税の計算と納付

### 2. 為替システム (Forex System)
- **内国為替**:
  - 全銀システム（Zengin System）連携
  - 振込依頼の受付、送金指示、入金通知
  - 組戻し、不渡り処理
- **外国為替**:
  - SWIFT MT103/MT202メッセージの生成と受信
  - 為替レートのリアルタイム更新と管理
  - 多通貨口座間の送金

### 3. 融資システム (Loan System)
- **融資管理**:
  - 融資申込受付、審査ワークフロー
  - 融資実行（一括、分割）
  - 担保管理（評価額更新、担保権設定）
- **返済管理**:
  - 返済スケジュールの生成（元利均等、元金均等）
  - 自動引き落とし、延滞管理、督促状発行
  - 繰上返済処理、条件変更

### 4. 決済システム (Payment System)
- **即時決済**:
  - クレジットカード決済代行
  - QRコード決済連携
- **大量決済**:
  - 給与振込、口座振替の一括処理
  - ネッティング処理

---

## 非機能要件 (Non-Functional Requirements)

### 1. パフォーマンス (Performance)
- **スループット**: 10,000 Transactions Per Second (TPS)
- **レスポンスタイム**: API応答時間 1秒以内 (99パーセンタイル)
- **バッチ処理**: 夜間バッチ処理を3時間以内に完了

### 2. 可用性 (Availability)
- **稼働率**: 99.999% (年間ダウンタイム5分以内)
- **冗長構成**:
  - 全コンポーネントの二重化以上 (Active-Active/Active-Standby)
  - フェイルオーバー時間 30秒以内
- **災害対策**:
  - ディザスタリカバリ (DR) サイトへのリアルタイムデータ同期

### 3. セキュリティ (Security)
- **データ保護**:
  - 保存データ (Data at Rest) のAES-256暗号化
  - 通信データ (Data in Transit) のTLS 1.3暗号化
- **認証・認可**:
  - OAuth 2.0 / OpenID Connect によるAPI認証
  - 多要素認証 (MFA)
  - ロールベースアクセス制御 (RBAC)
- **監査**:
  - 全操作ログの記録と改ざん検知 (ブロックチェーン技術の活用も検討)
  - Basel III 準拠、AML/CFT 対応

### 4. 拡張性・保守性 (Scalability & Maintainability)
- **マイクロサービスアーキテクチャ**: 機能ごとの疎結合な設計
- **コンテナ化**: Docker/Kubernetes によるオーケストレーション
- **自動化**: CI/CD パイプラインによる自動テスト・自動デプロイ
