# Test Strategy

## 1. 各テストケースの具体的なシナリオ

`test_transfer_service.py` を中心とした、主要なテストケース（シナリオ）を以下に定義します。

| テストID | テストケース名 (シナリオ) | 前提条件 (Given) | 操作・入力 (When) | 期待結果 (Then) |
|---|---|---|---|---|
| **TC-TF-001** | **正常系振込** | ・送金元(A)残高: 100,000円<br>・送金先(B)残高: 0円<br>・両口座: ACTIVE | AからBへ 50,000円 振込 | ・A残高: 50,000円<br>・B残高: 50,000円<br>・取引ステータス: COMPLETED<br>・手数料: 正しく引かれていること |
| **TC-TF-002** | **残高不足エラー** | ・送金元(A)残高: 1,000円<br>・振込額: 50,000円 | AからBへ 50,000円 振込 | ・`InsufficientBalanceError` が発生<br>・A残高: 変更なし (1,000円)<br>・取引記録なし（またはFAILED） |
| **TC-TF-003** | **口座凍結エラー** | ・送金元(A): FROZEN<br>・送金先(B): ACTIVE | AからBへ振込試行 | ・`AccountFrozenError` が発生<br>・残高変動なし |
| **TC-TF-004** | **限度額超過** | ・送金元(A)日次限度額: 100万円<br>・本日既振込額: 0円 | AからBへ 200万円 振込 | ・`DailyLimitExceededError` が発生<br>・残高変動なし |
| **TC-TF-005** | **高並列処理（同時実行）** | ・送金元(A)残高: 1,000万円<br>・送金先(B)残高: 0円 | 100スレッドで同時に A→B へ 1万円ずつ振込 | ・デッドロックが発生しないこと<br>・A残高: 900万円 (100万減)<br>・B残高: 100万円 (100万増)<br>・取引履歴が100件記録されること |
| **TC-TF-006** | **2PC途中での障害** | ・外部銀行振込<br>・Sagaパターン実行中 | 外部API呼び出し後にネットワーク切断（タイムアウト） | ・ロールバック（補償トランザクション）が実行されること<br>・A口座へ返金処理が行われること<br>・取引ステータス: FAILED |

## 2. カバレッジ目標

品質保証のため、各モジュールに対して以下のコードカバレッジ（C1）を目標とします。

| モジュール (ディレクトリ) | 目標カバレッジ | 理由・備考 |
|---|---|---|
| `core/customer/` | **90%** | 顧客情報は変更頻度が低いため、高カバレッジを維持。 |
| `core/account/` | **90%** | 残高管理はシステムの核であり、バグは致命的。 |
| `core/transaction/` | **95%** | **最重要領域**。金銭を扱うロジックは徹底的にテストする。 |
| `infrastructure/transaction/` | **85%** | DB接続や外部API連携を含むため、モックを活用して可能な限りカバー。 |
| `infrastructure/security/` | **90%** | 認証・認可ロジックの脆弱性を防ぐため。 |
| `core/loan/` | **85%** | 計算ロジックが複雑なため、パラメータテストを重点的に行う。 |
